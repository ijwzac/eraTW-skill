# 14. 日记系统（DIARY）写作速查

角色日记：玩家用**指令 406「翻看日记本」**读，或每日结束时以「daily 日记事件」自动读一页。写日记要实现 4 个引擎标签 + 遵守一套 `DIARY` 槽位状态机。**踩错任一条，日记就会"只有一页/空白页"读不出**（露娜初版就是全踩了）。

## 入口与"在场看不到日记"的真相
- 入口 = 指令 **406**（`ERB\コマンド関連\COMF\日常系\COMF406 日記を読む.ERB`）。是否出现由 `@COM_ABLE406` 决定。
- **`@COM_ABLE406:233` 有一条硬门控**：`SIF !TALENT:TARGET:恋慕 && !(FLAG:70 || !SHIRAHU(TARGET)) && TARGET → RETURN 0`。即**角色本人神志清醒地在场、且还没恋慕你时，禁止当面翻她日记**——这是引擎的隐私/合意设计，**不是 bug**。要能读须满足其一：她**恋慕**你（愿意分享）/ **时停**中(`FLAG:70`)/ 她**被夺心**(`!SHIRAHU`)。她不在场时你进她私室，则走"偷看枕头下日记本"入口。

## 四个标签（职责）
| 标签 | 时机 | 职责 |
|---|---|---|
| `@DIARY_K{id}_EXIST` | 每次询问 | `RETURN 1` 才启用日记 |
| `@DIARY_BEFORE_CHECK_K{id}` | 每日结束 | 设 `MAX_DIARY_PAGE:{id}:0`、按条件把 `DIARY:{id}:{页}` 置 2/3、必要时 `CALL CHARA_DIARY_PAGESETTING` |
| `@DIARY_TEXT_K{id}(PAGENUM, MODE, PAGECOUNT)` | 实际显示 | `SELECTCASE PAGENUM` 打正文。**参数名是自定义的，body 头三行必须 `#DIM PAGENUM`/`#DIMS MODE`/`#DIM PAGECOUNT` 声明**（否则 Lv2 警告、读进来是 0）。`MODE`="デイリー"或"指令" |
| `@DIARY_AFTER_CHECK_K{id}` | 每日读后 | 清理临时 flag（可空 `RETURN 0/1`） |

## `DIARY:{id}:{页}` 状态机（取值）
- `0` = 未解锁，读不到。
- `1` = 既读：daily 不再读；指令可读（**前提该物理页已登记 PAGESET**）。
- `2` = 未读·**当日 daily 自动读一页**（读后→1）；被读之前指令读不到。
- `3` = 未读·**写入即可用指令读**（读后→1）。**设 3 必须紧跟 `CALL CHARA_DIARY_PAGESETTING({id}, {页})`**。
- 可读页计数用 `GROUPMATCH(DIARY, 1, 3)`。

## `PAGESET:{id}:{物理页}` = 该物理页登记的日记编号
- 指令读页循环 `@CHARA_DIARY_COM` 里有 **`SIF !PAGESET:{id}:{DCOUNT} → BREAK`**：物理页没登记就**立即断页**（＝"只有一页/日記到此结束"的根因）。
- 登记者 = `@CHARA_DIARY_PAGESETTING(id, 页)`（把日记号填进第一个空物理页）。**设 code 3 时你要自己 CALL 它；code 2 由每日驱动读到该页时自动 CALL。**

## 每日挑页规则
每日结束 `@CHARA_DIARY_AFTERTRAIN`：只显示**第一个 `DIARY==2`** 的页，显示后置 1；**其余仍为 2 的页当天全被重置为 0 作废**。→ 重要事件（告白/恋人）放**小编号页**，免得被同日别的 2 顶掉。

## 常见坑（露娜初版全踩了）
1. **忘 `CHARA_DIARY_PAGESETTING`**：设了 code 3 却不登记 → 指令读页 `SIF !PAGESET BREAK` 立即断页。
2. **把状态写成布尔 0/1** 而非状态码 2/3：值 1=既读，daily 不读、缺 PAGESET 指令也读不出 → 两条路都死。
3. **用了禁用槽 `DIARY:{id}:0`**：引擎两个循环都从页 **1** 起，页 0 不可用。
4. **解锁条件漏 `== 0` 守卫**：`IF DIARY:{id}:{n} == 0 && <条件>` 才对；否则每天覆盖、与既读状态打架。
5. **`SELECTCASE PAGENUM` 用 0-based**：引擎传 1-based，对不上就落 `CASEELSE`（＝"空白页"）。
6. **PAGESET 脏槽残留 → 改过页结构/换版本后读到「空白页」**（本项目实测踩到）：`CHARA_DIARY_PAGESETTING` 只往「第一个空物理槽」追加、**从不回收**。一旦你增删/重排逻辑页、或玩家存档来自旧版本，旧的 `PAGESET:{id}:{槽}` 会一直指向**已无 `CASE` 正文的逻辑号** → 指令读把它们显示成 `CASEELSE`（空白页），还可能把真正文挤到后面。**症状**：日记里夹一堆空白页、或某页读不出。**根因**：`IF DIARY:{id}:N==0 && 条件` 这种「只首次登记」写法碰上旧存档里 `DIARY:{id}:N` 已非零 → 新页不登记、旧脏槽又不清。**解法见下方「自愈式 BEFORE_CHECK」**。

## 进阶：让日记「随进程变丰富」

### 自愈式 BEFORE_CHECK：每次清空 PAGESET 再按当前条件重建（推荐，免疫脏槽 pitfall #6）
只要角色日记**全用状态 3**（随时指令读、不走 daily 状态 2），`PAGESET` 就完全由 `BEFORE_CHECK` 掌控，可每次清空重建：
```
@DIARY_BEFORE_CHECK_K{id}
MAX_DIARY_PAGE:{id}:0 = 5
;★先清空物理槽（防旧存档/改版残留脏槽显示成空白页）
FOR LOCAL, 1, MAX_DIARY_PAGE:{id}:0 + 1
	PAGESET:{id}:LOCAL = 0
NEXT
;逐页：满足条件→(首次)置状态3、(每次)登记物理槽。SIF ==0 只在首次置3，保留既读态(1)。
IF <解锁条件1>
	SIF DIARY:{id}:1 == 0
		DIARY:{id}:1 = 3
	CALL CHARA_DIARY_PAGESETTING({id}, 1)
ENDIF
IF <解锁条件2>
	SIF DIARY:{id}:2 == 0
		DIARY:{id}:2 = 3
	CALL CHARA_DIARY_PAGESETTING({id}, 2)
ENDIF
RETURN 1
```
要点：①清空范围覆盖到 `MAX`；②`SIF DIARY==0` 保留既读态；③`PAGESETTING` **无条件重登记**，使物理槽＝当前已解锁页的顺序、无脏槽。
⚠**生效时机**：`BEFORE_CHECK` 只在**每日结束**被调用（指令读 `@CHARA_DIARY_COM` 不调它），故改动/自愈要**过一个游戏日**才在指令读里体现。

### 事件驱动页：某事件发生后日记多一页、内容随之更新
引擎**不会**自动把事件写进日记——要在事件 handler 里置一个私有 CFLAG（+可选存文本/计数），再让某页以它为解锁条件、正文引用它。范例（收到评价≥800 的挚爱礼物 → 解锁「礼物」页，正文显示最近礼物名与累计件数）：
```
;GIFT 事件 handler 里：
IF 評価点 >= 800
	CFLAG:{id}:1081 = 1              ; 解锁「礼物」页
	CSTR:{id}:81 = %GIFT_NAME%       ; 记住最近礼物名（CSTR 槽≥40 通常空闲）
	CFLAG:{id}:1082 += 1             ; 累计件数
ENDIF
;BEFORE_CHECK 里：以 IF CFLAG:{id}:1081 为解锁条件登记该页
;DIARY_TEXT 对应 CASE 里：正文用 %CSTR:{id}:81% / {CFLAG:{id}:1082} 渲染 → 内容随礼物更新
```
同理可做「初吻后」「第一次约会后」「某节日」等事件页。私有槽用作者保留区（`CFLAG 1000-1999`、`CSTR ≥40`），别撞引擎槽。

### 真·逐条累积的无限日记（进阶，仿引擎 MASTER_DIARY）
要「每次发生就新增一条、可无限翻页」，固定 `CASE` 页做不到；可仿引擎主角日记：用一个私有 `CSTR`/`SAVESTR` 以 `//` 分隔累积条目、再自写翻页显示（见引擎 `CHARA_DIARY.ERB` 的 `@MASTER_DIARY_WRITE`/`@READ_MASTER_DIARY`：`SAVESTR:1` 存、`STRCOUNT`/`SPLIT` 分条、超上限丢旧）。成本较高；一般角色用「事件驱动页 + 内容随状态更新」已足够。

## 可复用骨架（正确版）
```
@DIARY_BEFORE_CHECK_K{id}
MAX_DIARY_PAGE:{id}:0 = 3                          ; 实际最大页号
IF DIARY:{id}:1 == 0 && CFLAG:{id}:面識            ; 每条：==0 守卫 + 解锁条件
	DIARY:{id}:1 = 3
	CALL CHARA_DIARY_PAGESETTING({id}, 1)          ; code 3 必须登记
ENDIF
IF DIARY:{id}:2 == 0 && CFLAG:{id}:好感度 >= 500
	DIARY:{id}:2 = 3
	CALL CHARA_DIARY_PAGESETTING({id}, 2)
ENDIF
RETURN 1

@DIARY_TEXT_K{id}(PAGENUM, MODE, PAGECOUNT)
#DIM PAGENUM
#DIMS MODE
#DIM PAGECOUNT
SELECTCASE PAGENUM                                 ; 1-based，与 BEFORE_CHECK 页号一一对应
	CASE 1
		PRINTFORML …第1页正文…
	CASE 2
		PRINTFORML …第2页正文…
	CASEELSE
		PRINTFORML （空白页兜底）
ENDSELECT
RETURN 1
```
- 想要"daily 每天自动写一页、之后可回看"就把 code 设 **2**（不用手动 PAGESETTING，每日驱动会登记）；想要"解锁即随时可翻"就设 **3** + PAGESETTING。
- 更省心的做法：照 **K70（小铃）** 的"每页 `@DIARY_K{id}_{n}_HAPPEN`（判条件+返回码）+ `@DIARY_K{id}_{n}`（正文）成对" 模板，`BEFORE_CHECK` 里循环 `TRYCALLFORM`，天然正确、易扩到上百页。
- 丰富样板：**K70 `070 Kosuzu\小鈴\M_KOJO_K70_日記.ERB`（简易版）**、**K42 `042 Hatate\はたて\M_KOJO_K42_日記.ERB`（手写版，7-24 行是最完整官方注释）**。（注：Star/K7 没有日记系统。）
