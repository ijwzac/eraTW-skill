# 状态总线命名空间（完整参考）

## 4. 状态总线（state-bus）

状态总线是每个口上正文读取的*词汇表*。掌握它，就是「能跑」的口上与「对味」的口上之间的差别。

约定：`<NAMESPACE>:<CHAR_ID>:<SLOT>`（省略 CHAR_ID 时默认为 TARGET）。所有槽位都通过 `CSV/<file>.csv` 解析。

### 4.1 逐角色命名空间

> **重要——此处列出的槽位名是理想化的，未经核实。** eraTW 语料存在多个分支；某些槽位名在本分支上不同（简体中文 vs 日文汉字变体，某槽位在一个分支存在而另一个分支没有）。**在代码中使用前，务必 grep 实际的 `CSV/<file>.csv` 取得逐字节精确的槽位名。** 以下是我们实践中撞到的具体不匹配案例：
> - `约会中`（简体 约）才是规范的 CFLAG 行；`約会中`（日文 約）无法解析。
> - `BASE:N:疲労` *不是* 本分支 `CSV/Base.csv` 中的槽位。用 `BASE:N:気力 < MAXBASE:N:気力 / 2` 作为规范的「疲倦」判定。
> - `TFLAG:逢瀬時間` *不在* 本分支的 `CSV/TFLAG.csv` 中。没有通用的「距上次相见的天数」TFLAG；请用一个你自己掌控的私有 CFLAG 槽位（例如 `CFLAG:N:1080 = DAY`，再与今天作差）。

### 4.3 位置代码（`現在位置` / `自宅位置` / `初期位置`）

位置代码是**复合的**：百位及以上的位编码区域（世界地图），末两位编码具体地点。`CFLAG:MASTER:現在位置 / 100` 可还原出区域；访问处理器正是这样做的（`COMF697 部屋を訪ねる.ERB`）。地点名存放在 `CSV/Str.csv` 中。

三个并存的命名空间（同一房间会出现）：
- **绝对基础房间 `0–99`**——角色*在其自己家的地图上*的真实内部房间，例如 `33 = 露娜私室`，`32 = 桑尼私室`。`CFLAG:MASTER:現在位置 == 33` 意味着「实际站在那个房间里」，仅当 MASTER 共同居住在那张 家 地图上时才可达。
- **区域节点 `~6000+`**——通过 散步/移動 走过的某区域的户外/区域单元格，例如 `6005 = 妖精的大樹`，`6002 = 神社境内`。
- **`8000+` 镜像**——基础房间的一份平行副本（`8033 = 露娜私室`），用于某些非居住情境。

**共享的「拠点共通」房间是计算得出的**（`ERB/MOVEMENTS/物件関連/PLACE_拠点共通.ERB`），所以其代码依赖区域（通常为 3 位）：
- `OMANEKIBEYA()` = 待客室 = `98 + MAIN_MAP*100`
- `SUKIMA()` = 隙間空間 = `99 + MAIN_MAP*100`
- `ROAD_TO(mapid)` = 约会道中 = `97 + mapid*100`

**房间专属对话的陷阱**（例如「她布置过的卧室」台词）：通过 訪問房間[697]→部屋に入る（`OMANEKI_ENTER`）访问一个*非居住*角色的房间，会把 MASTER 和房主**双方**都传送到 `OMANEKIBEYA()`（通用的 待客室），**而不是**房主真实的房间代码。所以她的真实房间（例如 `33`）只有在 MASTER 与她共居于她的地图上时才被占用；否则你们会在 `98 + MAIN_MAP*100` 相见。房间风味口上要以真实的基础代码作为守卫，并记住被访问的情形落在 待客室 里。在游戏中用 `PRINTFORML {CFLAG:MASTER:現在位置}` 确认实际代码。
