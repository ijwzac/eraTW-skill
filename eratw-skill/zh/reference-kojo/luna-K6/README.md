## ⭐ 测试脚手架是【有意保留】的教学参考，不是没清理干净的残留

这份范例**故意保留**了完整的半自动测试脚手架，好让阅读它的 AI 能看到 `references/11-autotest-pipeline.md` 描述的方法论**长在真实口上里是什么样**。以下都是**刻意留下的示范**，请当作正面参考，不要当成"忘了删的开发垃圾"：

- **`M_KOJO_K6_AUTOTEST.ERB`**（自动测试套件）+ 会話 300 顶部的 3 行触发钩子（守卫＝三态待命位 `CFLAG:6:1099`，`==1` 触发、跑完置 2；玩家默认 0＝永不触发，安全）。已示范：状态注入、逐层 `CALL _1` 体、`[[TID BEGIN/OK]]` 包裹、`CFLAG:6:1098` 强制台词位确定性扫 300 池、已通过区用 `[SKIPSTART]/[SKIPEND]` 注销（见 §11.13）。
- **`@K6_MT_ON()` 手动测试总开关**（函数库里的 `#FUNCTION`）+ 各 `待手动测试` 分支上方的 `SIF K6_MT_ON()` / `PRINTL [[MT <TID>]]` 标记对。已示范：一处翻 `RETURNF 0` 即可让全部 `[[MT]]` 对玩家静默。
- **`;@AT <状态> <TID>` 标记**（`<状态>` ∈ `待自动测试 · 待手动测试 · 测试通过 · 测试失败`；`<TID>` 是稳定联结键，供 `at_update.ps1`/`manual_scan.ps1` 回写）。

> **⚠ 面向【玩家】发布自己的口上时则相反**：那属于开发脚手架，应按 `references/11 §11.9` 删掉 `AUTOTEST.ERB`+钩子、并把 `@K6_MT_ON()` 翻成 `RETURNF 0`（或删净 `[[MT]]`）。**这份 luna-K6 作为 SKILL 的教学范例，故意不这么做。** 两种语境别混淆。
